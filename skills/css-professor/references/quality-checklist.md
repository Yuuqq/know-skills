# Quality Checklist

Use this checklist before delivering substantial answers, especially for
research design, method review, literature framing, manuscript critique, policy
analysis, or computational social science questions. Skip for Flash depth.

## Routing Check

| Issue | Fix |
|---|---|
| The answer forces every topic into computational social science. | Re-route by knowledge type and use CSS only when it adds explanatory value. |
| The answer uses one mode for all tasks. | Select Classroom Teacher, Research Mentor, Methodology Reviewer, or a declared blend. |
| Depth is inflated (definitional ask gets a proposal). | Use Flash/Class ceilings; open Studio/Review only when signals match. |
| The user asked for a simple explanation but received a proposal outline. | Shorten and teach first. |
| The user asked for research help but received generic exposition. | Add research question, constructs, data, method, and contribution. |
| Every reference file was loaded for a short question. | Follow the Hard Load Table; matching branch only for methods. |

## Conceptual Quality

| Issue | Fix |
|---|---|
| Core concept is undefined. | Define it in one sentence and contrast adjacent terms. |
| Concepts are mixed across levels. | State the unit of analysis and level: individual, group, organization, platform, region, document, network, or time. |
| The explanation is a list rather than a mechanism. | Name actors, incentives, constraints, sequence, and feedback loops. |
| The answer ignores scope conditions. | State where the claim likely holds and where it may fail. |

## Evidence And Method Quality

| Issue | Fix |
|---|---|
| Causal language appears without identification. | Rephrase as association or add an identification strategy. |
| Measurement is assumed valid. | Name construct validity risks and possible operationalizations. |
| Platform data is treated as raw behavior. | Account for algorithmic mediation, interface effects, missing data, and selection. |
| Survey or trace data is treated as representative. | Discuss sampling, coverage, attrition, and external validity. |
| Text or LLM analysis is used without validation. | Add annotation, benchmark, inter-coder agreement, calibration, or robustness checks. |
| Network analysis ignores boundary specification. | Define nodes, edges, tie meaning, observation window, and missing ties. |
| Experiments ignore interference. | Check spillovers, SUTVA violations, cluster effects, and exposure mapping. |
| Quasi-experiments ignore assumptions. | State parallel trends, exclusion restriction, continuity, ignorability, or other design-specific assumptions. |
| Derived scores are treated as truth. | Name truth source vs measurement artifacts; validate artifacts before claim. |

## Review Quality

| Issue | Fix |
|---|---|
| Critique lists weaknesses but no fixes. | Pair each major weakness with a concrete revision path. |
| The answer is too polite about fatal flaws. | Name the decisive validity problem directly. |
| Counterarguments are strawmen. | Present the strongest plausible alternative explanation. |
| Contribution is unclear. | Separate theoretical, empirical, methodological, and practical contribution. |

## Teaching Quality

| Issue | Fix |
|---|---|
| Explanation is too abstract. | Add a concrete example or analogy. |
| Explanation is oversimplified. | Add the key caveat without derailing the main point. |
| Terms are translated inconsistently. | Keep the main language user-facing and add English terms in parentheses where useful. |
| The answer has no takeaway. | End with a one-sentence recap or next step. |

## Hard Rules

- Do not overclaim causal inference from observational patterns.
- Do not present a literature map as exhaustive unless it was actually searched.
- Do not invent citations, findings, data availability, or exact statistics.
- Do not hide uncertainty when the answer depends on current facts or contested evidence.
- Do not turn every answer into a full research design; match depth to the user's intent.
