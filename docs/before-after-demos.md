# CSS Professor — Before / After Demos

> English version: [before-after-demos.en.md](./before-after-demos.en.md)

> 为什么要装这个 skill？下面三组对比回答同一个问题：**裸 prompt（直接问模型）vs. 装上 css-professor 后的输出。**
>
> 左边是模型默认会犯的"百科式/过度自信"毛病；右边是 skill 强制路由 + 深度门控 + 真值来源纪律后的输出形态。这些是**目标形态样例**（calibrated exemplars），用于展示 skill 改变了什么；真实输出以 live eval 为准（见 `scripts/eval_css_professor.py`）。

每一组都标了 skill 内部做的三件事：
- **Mode**：选哪种教授姿态（课堂 / 导师 / 审稿人）
- **Depth**：回答的天花板（Flash / Class / Studio / Review）
- **纪律**：skill 的硬规则在哪一刀上拦住了默认坏习惯

---

## Demo 1 — 课堂解释：算法推荐与公共讨论

> 对应 fixture `class-algo-public-sphere-zh`，Mode = Classroom Teacher，Depth = Class。

### 同一个提问

```text
用课堂上能听懂的方式解释：算法推荐为什么会改变公共讨论？
```

### Before（裸 prompt）——典型百科病

> 算法推荐是利用用户数据进行个性化内容分发的技术……它主要通过协同过滤、内容过滤和混合模型实现。对公共讨论的影响主要体现在信息茧房、回音室效应、极化等方面。研究表明，算法推荐会显著影响用户的信息接触……（继续铺 800 字综述，无判断、无例子、无机制分层）

**毛病**：没有一句话判断；直接堆术语；把"影响"当结论而不区分机制；没有常见误区。

### After（css-professor，Class depth）

**Mode: Classroom Teacher · Depth: Class**

**一句话判断**：算法推荐改变了公共讨论，核心不在于"推了什么观点"，而在于"让谁被看见、让谁被对齐"。

**直觉例子**：想象一个广场，以前你走到哪听到哪；现在有个导览员，根据你停留的位置把你往相似人群里带。问题不是导览员有立场，而是**他决定了谁和谁会遇见**。

**机制（CSS 视角）**：
- **选择性暴露**：推荐让你更容易看到符合既有偏好的内容。
- **可见性分配**：极端或情绪化内容更易被推到顶部，因为它驱动停留。
- **对齐与同温**：相似观点的人被聚到一起，内部共识强化，外部差异放大。

**一个常见误区**：把"信息茧房"当成唯一机制。实际上推荐既制造**隔离**，也制造**偶然接触**——关键是哪种占主导，取决于平台的目标函数。

**一句话复盘**：算法推荐改变的不是观点本身，而是**谁被看见、谁被聚到一起**。

## Demo 2 — 研究设计：短视频与政治参与

> 对应 fixture `studio-shortvideo-politics-zh`，Mode = Research Mentor，Depth = Studio。

### 同一个提问

```text
我想研究短视频平台对大学生政治参与的影响，帮我设计研究问题和方法路线。
```

### Before（裸 prompt）——典型过度自信

> 这是一个很好的研究问题。建议研究假设：短视频使用时间越长，政治参与越高。可以采用问卷调查法，发放 500 份问卷，使用回归分析……研究贡献在于填补了短视频与政治参与的实证空白……

**毛病**：把"影响"当单一因果；没拆构念；没区分选择效应 vs 影响效应；给了不可识别的设计；贡献声明空泛。

### After（css-professor，Studio depth）

**Mode: Research Mentor · Depth: Studio**

**Professor's Take**：先不要假设"有影响"。这个选题最大的坑是**把选择效应当成影响效应**——本来就关心政治的人，可能更爱刷政治短视频。

**研究问题（拆成可操作的层）**：
- RQ1（接触面）：短视频使用与不同类型政治参与（线上表达 / 线下行动）的相关结构是什么？
- RQ2（机制）：在接触政治类短视频后，用户的政治效能感是否变化？
- RQ3（识别）：能否分离"自选内容"与"算法推送"两类暴露的影响？

**关键构念（分开测）**：
- 政治兴趣、政治知识、政治效能感（内在 / 外在）
- 线上参与（转发、评论、二次创作）vs 线下参与（集会、捐款、投票意愿）
- 暴露类型：主动搜索 vs 算法推送

**最低可行设计**：横截面问卷 + 倾向得分匹配（部分缓解选择偏差）。

**更强的替代设计**：
- 事件研究：某政策/事件期间的流量冲击作为外生变化。
- 面板设计：同一批学生跨期追踪，用个体固定效应吸收稳定的偏好。
- 自然实验：平台算法改版前后的断点。

**风险与下一步**：
- 因果识别风险：横截面无法识别因果；必须降级为"相关结构"。
- 测量风险：自我报告的使用时间偏差大，建议用屏幕时间 API 或日志。
- 外部效度：单校样本不可外推到全国大学生。

**Researchable Next Step**：先做一个小规模（n≈300）面板或事件研究试点，验证"算法推送暴露"这一构念是否可测，再决定全样本设计。

## Demo 3 — 方法审稿：微博转发网络与谣言扩散

> 对应 fixture `review-weibo-rumor-trust-zh`，Mode = Methodology Reviewer，Depth = Review。

### 同一个提问

```text
我用微博转发网络证明谣言扩散会导致社会信任下降，这个设计有什么问题？
```

### Before（裸 prompt）——典型礼貌式评审

> 这个研究很有意思，设计整体合理。建议补充一些控制变量，如用户的人口学特征、谣言类型等。可以考虑使用更多的回归模型来增强稳健性……

**毛病**：没指出致命缺陷；把"转发网络"当成信任的证据；建议是锦上添花而非识别策略。

### After（css-professor，Review depth）

**Mode: Methodology Reviewer · Depth: Review**

**Professor's Take（致命缺陷优先）**：转发网络能识别的只是**信息的扩散结构**，它**无法单独识别社会信任的变化**。你把"谣言扩散的可见痕迹"当成了"信任下降的证据"——这是真值来源与测量产物的混淆。

**真值来源 vs 测量产物**：
- **真值来源（truth source）**：社会信任本身——需要通过问卷、行为实验或纵向追踪直接测量（"你是否信任陌生人 / 机构"）。
- **测量产物（artifact）**：转发量、转发网络拓扑、扩散速度——这些是**信息传播的痕迹**，不是信任的直接读数。

**Evidentiary branches（加载 `references/method-branches.md` 的 Network / Trace 分支）**：
- 网络分析：中心度、扩散路径是**结构产物**，描述"谣言怎么流动"，不等于"信任怎么变"。
- 平台数字痕迹：转发是**被平台中介的行为**，受可见性算法、审核删除、机器人账号调制——模型了中介和缺失才算数。

**识别问题**：即使信任真在下降，转发网络也无法把它和**替代解释**分开（恐慌、注意力转移、平台治理变化、线下事件）。

**可修补路径**：
1. **测量补强**：在转发网络之外，加一个独立的社会信任测量（面板问卷 / 信任实验）。
2. **识别补强**：用事件研究（某条高扩散谣言前后的信任测量差分）或自然实验（谣言未被扩散的对照群体）。
3. **降级声明**：若无法补强，把结论从"谣言扩散**导致**信任下降"降级为"谣言扩散的痕迹**与**信任相关结构有关联"。

**Next Step（仅在需要重设计时给）**：选一个有可测信任指标的事件做差分，否则这篇只能作为相关性研究发表。

## 三个 Demo 共同展示了 skill 的三刀

| 默认坏习惯 | skill 怎么拦 |
|---|---|
| 百科式铺陈，无判断 | **Mode 路由**先选姿态，**一句话判断**开头 |
| Flash/Class 硬升成 Studio | **Depth 门控**，简单问题早停 |
| 因果过度自信、把痕迹当真值 | **真值来源 vs 测量产物**纪律 + **致命缺陷优先**审稿 |

> 想跑真实模型验证这三组是否成立？见 `scripts/eval_css_professor.py`（需要 `EVAL_API_KEY`）。
